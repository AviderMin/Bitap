# Bitap ADB 使用体验记录

时间：2026-11-07，约 17:11–17:15（Asia/Shanghai）。

## 结论

常用短句已有基本可用性，但长整句候选和简拼仍明显不足。目前更适合拆成短词输入，尚不能据此判断适合作为全天主力输入法。此次测试验证真实编辑框结果，没有把编译或单测通过等同于好用。

- 设备：ADB `fe4ab855`，model `22021211RC`，1080×2400。
- 输入法：`com.bitap.keyboard/.ime.BitapImeService`。
- 安装时间：2026-11-07 17:10:39，versionName 0.1.0。

- 注意：此包与第三轮源码审查对应的 `5A083A...` 安装包不同。本轮结果仅适用于手机上的新安装包，不能自动归因到仓库 dac6cc2 的实现。
- 主要操作环境：Via 地址栏，真实触摸键盘；通过 uiautomator 读取 EditText 文本。之后准备本地 textarea 测试，但出现并发操作，未完成这部分验收。

## 未下结论的部分

- 第一次快速注入 nihao 观察到 nhao，但未排除转屏、输入连接变化或并发操作，不能据此断言键盘漏字。
- 英文、数字、连续退格组出现界面变化和额外输入，结果污染，不能标 PASS 或 FAIL。
- 试验期间手机 user_rotation 在未由本轮修改时从0变回1；本地页出现本轮未输入的 ww。怀疑存在另一轮自动化或人工操作。发现后停止触摸，没有删除该段未知来源文字。
- 横屏开始时键盘已是紧凑布局，地址栏可见，较上一轮截图有所变化；未完整输入长句或展开候选，因此不沿用旧包“横屏不可用”的结论，也不把新包横屏判为通过。
- 未完成 AI、真实双指、精确时延与长期稳定性测试。ADB 不能感受真实触觉、键帽舒适度和手指误触率。

## 操作边界与清理

本轮没有主动点击回车/前往来提交测试查询。不过过程中观察到浏览器出现“nh是什么意思”的搜索页；当时操作/界面受干扰，不能保证测试文字始终没有被浏览器提交，也不能把该页面变化当成输入法缺陷证据。

为隔离浏览器建议，曾创建临时本地 HTML textarea 和 localhost:8767 测试服务，通过 adb reverse 访问。停止测试后关闭该临时服务并移除本轮 tcp:8767 映射；未安装应用、未删除用户应用数据。并发控制被发现后不再强行恢复界面或覆盖未知输入。

## 下一轮优先事项

1. 固定一份明确源码/安装包对应关系，并保证测试时手机只有一个操作者。
2. 把“明天上午十点见”等自然句子加入真实词库回归集，统计首选/前五命中率和修正次数；不要只优化 nihao、woaini 等少量演示词。
3. 增加简拼、混拼和同音词修正体验；先确认产品支持范围，再设计输入引擎。
4. 在离线本地 textarea 重新完成快打、双拇指、英文/数字、改错和横屏，以排除浏览器建议干扰。
5. 请用户实际连续使用10–15分钟评价振动、键位与疲劳感；这部分不能由 ADB 点击结果替代。
