## 1. v3 新来源不等于与完整训练语料零重合

现有 `check_v3_corpus.py` 对词典整句和 v1/v2 expected 做检查，没有对生产统计使用的全部 89,289 条 Tatoeba 训练句查重。换来源仓库无法自动排除不同仓库收录同一句话。

本次新增 `eval/v3/audit_training_overlap.py`，按 v2 manifest 验证完整 Tatoeba 源文件 hash，按 v3 manifest 验证冻结语料 hash。只输出计数、不打印 case ID、拼音、期望或候选、不执行引擎、不据样例调参。

实测汇总：

| 类别 | 条数 | 训练句规范化精确重合 | Jaccard ≥0.80 近重复（含精确） |
|---|---:|---:|---:|
| natural_short | 320 | 1 | 1 |
| natural_medium | 240 | 0 | 0 |
| natural_long | 41 | 0 | 0 |
| 合计 | 601 | 1 | 1 |

规范化只保留 U+4E00..U+9FFF；近重复为字符 bigram 集合 Jaccard，长度比至少 0.5，没有繁简转换或语义级检测。因此应表述为“新来源验收，存在已知 1 条训练句重合，其余在该规则下未检出”，不能写严格零重合或证明所有内容独立。该 1/601 的重合不支持把整套 v3 评测判为无价值。

当前 v3 601 条与首次成绩保持不动；后续如果排除该条，必须新版本、重新冻结并保留旧成绩，不能悄悄回写 v3。即使改名或重切同一批已曝光数据，也不能自动恢复盲测独立性。

复现：`python eval/v3/audit_training_overlap.py`。默认写 `build/v3-training-overlap-audit.json`，发现重合时退出码为 1；不是工具故障。数据或 hash 不可用时退出码 2，不能打印 PASS。该审计不自动并入已有全绿门禁，避免修改冻结资产来消除真实发现。

## 2. v2/v3 差值不能单独证明同源训练造成高估幅度

`EVALUATION_V3_BASELINE.md`、ADR 0002 里“证明 v2 分数被同源数据高估”的因果表述过强。v3 同时更换地区用词、句长比例、句子来源和过滤后的难度分布。观察到分数更低，足以说明旧 v2 不能代表该新来源表现，但不能把整个差值归因于训练重合。

建议统一表述：“v2 存在已确认的训练源重合；v3 在新来源上明显更低，提示跨来源泛化不足。当前实验没有隔离训练重合与分布变化各自的贡献。”

如果要量化同源训练的作用，需冻结同一评测样本，比较包含/不包含相应训练簇的统计资产；不得用两套不同样本的总分差直接代替消融。

## 3. 9.25pp 是固定组合的换词典效应，不是可加贡献

固定 Rime 最小方案换词表/权重后 Top1 下降 9.25pp，这个观测有效。它衡量整个替换操作的净影响，包括权重与搜索、切分的交互，不宜写“Rime 有 9.25pp 能力来自词典”，也不能再与解码器收益相加。

同词典仍缺少等价统计模型、候选组织和键事件输入；当前两个宿主方案都不能代表完整 Android 产品。先试完整实用方案再承担 JNI 集成成本，比只为收集 Android 性能而迁移一个质量明显不达标的最小配置更有价值。

另外，文档的“字符 n-gram 句子重排”不够精确：当前 `PinyinEngine` 默认 `SENTENCE_CORPUS_WEIGHT=0`、`SENTENCE_DICTIONARY_WEIGHT=0`；启用的统计信号包含路径扩展的上下文分数和词内分数。应写“字符 n-gram 统计参与解码/排序”，避免声称未启用的整句后重排已经在工作。

## 4. v3 的用途与校验强度

- v3 只有自然短/中/长句，不能单独验收 D06 错拼、D07 混排、快速多指和生命周期。它是自然句质量基线，仍需隔离的专项集合与事件/设备测试。
- v3 既声明一次性验收，就不能每次调参后反复看聚合分数决定方向；聚合反馈同样会影响模型选择。开发诊断在明确 dev 上做，冻结候选后才验收，并记录验收次数。
- `check_v3_corpus.check_source` 在全部 CC0 源文件缺失时直接 skipped 且不令总流程失败，archive 缺失也跳过 hash 校验。这可以作为轻量格式检查，但不足以称为完整溯源门禁。后续应区分离线轻量检查与需要完整原件的严格发布检查。
- 校验器还没有落实协议中的全部字符/最大拼音长度过滤验证；生成器当前做了过滤，不等于任意修改后的 TSV 都会被校验器拒绝。正式门禁需补齐一致性。
